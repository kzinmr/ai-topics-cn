# 智谱GLM（ChatGLM）— 中国最大級オープンソースLLM

## 概要

**智谱AI**（Zhipu AI）は、清華大学の技術を母体とする中国の大規模言語モデル企業であり、GLM（General Language Model）ファミリーを開発・公開している。初期のChatGLMシリーズから始まり、GLM-4.7、GLM-5、GLM-5.1、GLM-5.2、GLM-5.3へと急速に進化を遂げた。特筆すべきは、中国発のオープンソースLLMとして世界最大級のパラメータ規模を誇り、コード生成・エージェント制御・フロントエンドUI生成など幅広い領域で存在感を示している点である。

中国の開発者コミュニティ（掘金、V2EXなど）では、GLMシリーズへの言及が急増しており、[[deepseek]] や [[kimi-moonshot]] と並んで「国産LLM三強」の一角として議論されることが多い。

- Geminiと比較してUI生成品質で優位とする声も
- 一方、火山云（Volcengine）のCoding Planにおいては Doubao-Seed-2.0-Code と同梱されたが、一部ユーザーからは「力不足」との指摘

- エージェント制御（Agent Orchestration）に特化した最新モデル

### GLM-5.2（2026年6月22日リリース）

- **リリース日**: 2026年6月22日
- GLM-5.1から進化したモデルで、**スピードとシンプルさ**で開発者コミュニティから高い評価を受ける

### GLM-5.3（2026年8月発表）

- **概要**: Z.ai（智谱AI）が発表した最新モデル。現時点ではコーディングプラン限定で提供中、APIとHuggingFace（オープンウェイト）は今後2週間以内に公開予定
- **パラメータ規模**: 約**750B**（Kimi K3の約1/3）。小規模ながら多くのベンチマークでKimi K3を上回り、Claude Fable 5やGPT-5.6-Solに匹敵するスコアを記録
- **技術的特徴**: GLM-5.2と同一ベースモデルを使用し、**ポストトレーニング（RL中心）を大幅に拡張**。Z.aiブログでは「Scaling post-training is all we did for GLM-5.3」と明言
- **RL環境**: 「より多くの環境、より多様なタスク、より多くのコンピュートをトレーニングに費やす」というアプローチ
- **エージェントコーディング**: フロンティア級のエージェントコーディングベンチマークで最前線の性能

> 「Scaling post-training is all we did for GLM-5.3.」 — Z.ai公式ブログ

**cybersecurity（サイバーセキュリティ）能力:**

- GLM-5.3はZ.aiが今までで最もサイバーセキュリティタスクに適したモデルと位置づけ
- 脆弱性発見、エクスプロイト分析、複雑なマルチステップセキュリティタスクにおいて大幅な性能向上
- **段階的リリース戦略**: 安全パートナーがまずコントロールされた環境で評価し、その後API利用可能性を拡大、最終的にモデルウェイトを公開
- 推論監視にはリクエスト分類器とチェーンオブソート監視を導入

**中国LLM業界の構造的優位性:**

- **リリースサイクルの速さ**: Z.aiのリリースは数日単位で、OpenAIやAnthropicの数ヶ月と比較して桁違いに早い。この時間差がベンチマークでの競争力を維持する最大の要因
- **蒸留vsポストトレーニング**: 記事著者は蒸留が主因ではなく、RL環境・インフラ・アルゴリズムの組み合わせが鍵と分析
- **RLデータ産業の台頭**: 米国企業が中国ラボにRL環境を販売するビジネスが急成長中。同じRL環境を使用しつつ、中国ラボがより早くモデルをリリースする構造
- **清華大学との連携**: Z.aiは清華大学と密接な関係を維持し、優秀な人材プールを活用
- **ARR 10億ドル**: オンプレミスデプロイメント事業により年間売上高10億ドルに到達したとの報告
- **Benchmaxxing（ベンチマーク最適化）**: 記事著者は「業界標準」と指摘。米国企業も同様に戦略的にベンチマークを最適化しているが、公開タイミングの違いが中国ラボの優位性を生んでいる

## GLM-5オープンソースの衝撃

2026年4月、智谱AIがGLM-5（744Bパラメータ）をオープンソースとして公開したことは、中国AI業界に大きな衝撃を与えた。

**主なインパクト:**

1. **規模の突破**: 744Bパラメータは公開時点で世界最大のオープンソースLLM。[[deepseek]] のDeepSeek-V3（671B MoE）をも上回る密結合パラメータ数
2. **ベンチマーク性能**: SWE-bench 77.8はクローズドソースのトップモデル群と同等水準
3. **能力の質的変化**: 単なるコード補完ではなく、フルシステムアーキテクチャの設計能力を持つと評価された点が従来のOSSモデルと一線を画す
4. **開発者心理への影響**: 「シニアプログラマーすら危険」という表現が象徴するように、コーディング自動化の議論をさらに加速させた

掘金（Juejin）での当該記事は76いいねを獲得しており、中国技術コミュニティ内での関心の高さが窺える。

## 実戦での評価

### GLM-5.1によるマルチエージェント移行実験

ある開発者が、GPTで運用していた**23個のエージェント**をGLM-5.1に全面移行する実験を行った。

**結果のハイライト:**

| 項目 | 数値 |
|---|---|
| 移行エージェント数 | 23 |
| 1日のセッション数 | 15 |
| 1日のメッセージ数 | 1,556 |
| クラッシュ回数 | 0 |

- 完全なウェブサイトを構築、マルチエージェント協調パイプラインを実行
- **評価**: 「执行力比GPT强，但有个硬伤」（実行力はGPTより強いが、致命的な弱点がある）
- 具体的な「硬伤」（致命的欠点）の詳細は元記事を参照のこと

## 他モデルとの比較

### vs Claude 4.6

Claude 4.6がGLM-5に対して**10個の「毒問題」（adversarial questions）**を出題するという比較検証が話題を呼んだ。モデル間の直接対決形式のコンテンツは中国開発者コミュニティで高い関心を集めており、GLM-5のロバスト性を測る試金石として議論されている。

📎 出典: [掘金 — Claude 4.6 vs GLM-5「毒問題」対決](https://juejin.cn/post/7605885766167806004) `[Tier-1: 掘金/技術コミュニティ]`

### vs GPT

前述のエージェント移行実験において、GLM-5.1はGPTに対して「実行力」で優位とされた。ただし「硬伤」（致命的弱点）の存在も指摘されており、全面的な優位ではない。

### vs Doubao（豆包）

火山云（Volcengine）のCoding Planにおいて、GLM-4.7はDoubao-Seed-2.0-Codeと同梱提供されたが、一部のV2EXユーザーからは「弱すぎる」との評価を受けた。バンドル提供における主力はあくまでDoubaoであり、GLM-4.7は補助的な位置づけと見られている。

📎 出典: [V2EX — 火山云 Coding Plan](https://www.v2ex.com/t/1206049) `[Tier-2: V2EX/フォーラム]`

### 補足: Anthropicによる千問（Qwen）安全性実験

直接GLMに関する話題ではないが、関連する中国LLMエコシステムの動きとして、Anthropicが阿里巴巴の千問（Qwen）をAI安全性の制御可能性実験に使用したことが報じられた。「人类能管住AI吗？Anthropic用千問做了个实验」（人類はAIを管理できるか？ Anthropicが千問で実験した）。中国産OSSモデルが国際的なAI安全性研究の素材として採用される事例として注目される。

📎 出典: [36kr — Anthropic千問実験](https://36kr.com/p/3767822090777088) `[Tier-1: 36kr/テックメディア]`

## GLM-5詳細技術仕様（2026年2月-4月）

### 基本パラメータ

| 項目 | GLM-4.7 | GLM-5 |
|------|---------|-------|
| 総パラメータ | 355B | **744B**（MoE、アクティブ40B相当） |
| 前学習データ | 23T tokens | **28.5T tokens** |
| SWE-bench Verified | — | **77.8**（Claude Opus 4.5に匹敵） |
| Artificial Analysisランキング | — | グローバル4位、**オープンソース1位** |

### アーキテクチャの特徴

- **コードネーム "Pony"（小馬）**: 午年にちなむ命名。OpenRouter経由でClaude Codeに統合可能
- **MoE（Mixture of Experts）構造**: 744Bの総パラメータながら、推論時は40B相当のみをアクティブ化し効率を確保
- **Agentic Engineering**: 単なるコード生成からシステムアーキテクチャ設計へ能力が进化

### Claude Code連携での実戦能力

掘金ユーザー「AI袋鼠帝」のレビューによると：

1. **Plan Modeでの計画立案**: Claude Opus類似の詳細な633行の計画を出力。バグ修正や新機能実装の前に、論理的で実行可能な計画を立てる能力を持つ
2. **Playwright MCP自動调用**: ブラウザ操作を自律的に実行。各AIサイトのDOM構造を分析し、入力框・送信ボタン・テキスト取得を自動化
3. **自己反思サイクル**: 実行中にエラーが発生すると、自己で問題分析→修正→再テストのサイクルを繰り返す
4. **複数バグ一括処理**: 一度に4つの異なるバグを提示しても、条理清々に個別修复。他機能への影響なし
5. **実行時間**: 複雑なタスクでも40-50分で完了。その間開発者は別の作業が可能

### 価格・アクセス

- **z.aiで無料利用可能**
- **オープンソース**: GitHub / HuggingFace / ModelScopeで公開
- **中国国産チップ（万卡クラスター）上で稼働**: 公式が緊急増設中
- **Maxパッケージ**: 需要増加により抢手状態

### 実使用ケーススタディ

| ケース | 時間 | 結果 |
|--------|------|------|
| マルチAI比較ブラウザプラグインMVP作成 | 7分 | 前後端・DB含む完全なスタブ生成 |
| 既存プロジェクトのバグ修复+フロントリファクタ | 40分 | 主流程すべて修复、新機能追加 |
| Claude Code Plan Mode出力 | 633行 | 詳細な実装計画とタスク分割 |
