# 隐性结构塌缩 — LLM出力の「隠れた構造崩壊」

> **コンセプト分類**: プロンプトエンジニアリング / LLM理論
> **出典**: Juejin（掘金）— 2026-04-19
> **原作者**: 码事漫谈（juejin.cn/user/1972974802965230）
> **価値**: ★★★★☆ — 中国語圏独自のLLM理論的概念的知見

## 概要

「隐性结构塌缩」（隠れた構造崩壊）とは、大規模言語モデル（LLM）が明示的な制約がない状態で出力を行う際、**最も安全で一般的・平均的な出力構造に自発的に塌縮（collapsed）する現象**を指す。モデルの能力上限は高いにもかかわらず、指示が「尖锐でない」（鋭くない）場合、モデルは出力空間の探索を高確率領域に偏らせ、平穏で内容の薄い出力を生成してしまう。

この概念は、中国語圏の開発者コミュニティで日常的に観察される「AI出力がどれも 비슷見える」「洞見がない」という不満を理論的に体系化したものである。

## 核心の定義

```
平庸な出力 ≠ モデルの能力不足
平庸な出力 ＝ モデルへの「構造」制約が弱すぎる
```

大モデルの本質は次のtoken確率分布予測にある。指示が十分に「鋭い」（拘束的でない）場合、モデルは以下の高確率パスに自然に偏る：

| 高確率構造 | 具体的なパターン |
|-----------|----------------|
| **高频结构** | 総-分-総、对比表格（比較表）、SWOT分析 |
| **中性措辞** | 「值得注意的是」（注目すべきは）、「总体而言」（全般的に言うと） |
| **安全結論** | 「各有优劣」（それぞれ長所短所あり）、「根据实际情况」（状況に応じて） |

これは「幻觉」（ハルシネーション）ではなく、**確率の本能**である。モデルは「考えている」のではなく、高次元の完形填空（ Cloze test ）をしている。ユーザーが与える「空白」（制約）が多いほど、モデルは平均的な填充物を入れてしまう。

## 破解方法：强制低確率結構

### 方法1：逆向结构约束（逆向き構造制約）

「怎么写」（どう書くか）ではなく「**不准怎么写**」（何を禁止するか）を明示する。

| 平庸な制約 | 逆向制約（禁止事項） |
|-----------|---------------------|
| 「深入分析して」 | **禁止**: 「第一/第二/第三」「首先/其次/再次」を段落冒頭に使うこと |
| 「洞見のある結論を」 | **禁止**: 「综上所述」「各有优劣」式の安全結論 |
| 「論理清晰に」 | **强制**: 各观点の後に、その观点が最も反論されそうな理由を記述 |

逆方向制約の本質は**確率的空間の剪定（pruning）**である。剪定するのは「悪い書き方」ではなく、最も一般的で最も安全な構造パスである。

### 方法2：固定出力フォーマットによる非均匀分布の強制

自由テキストは最も塌縮しやすい形式。構造化された出力を強制することでこの慣性を打破できる。

例：
```
「3つの重要リスクを分析して」 ← 塌縮する指示

↓

以下のJSON構造で出力、各valueは20token不得超过：
{
  "最被高估的风险": "",
  "最被低估的风险": "",
  "最反直觉的风险": "",
  "唯一值得在Q3投入资源的": ""
}
```

JSON構造はモデルに「段落的思考」から脱却させる。各フィールドの文字数制限は**情報蒸留**を強制し、最後のフィールドの排他選択は**判断**而不是列出（罗列ではなく判断）を強制する。

### 方法3：極端案例への锚定

モデルの出力が平板平均的になるのは、モデルが「平均情況」で補間しているためである。極端な锚点を与えることで、出力分布の分散を显著に引き上げられる。

| 平庸な指示 | 锚点指示 |
|-----------|---------|
| 「特斯拉の競争戦略を分析して」 | まず以下2つの極端な分析フレームを読み、それらを反駁する形で第3の道を論じること：<br>フレームX（極端楽観）：TeslaのFSDは18个月以内に中国車に追い抜かれる<br>フレームY（極端悲観）：Teslaのブランドプレミアムは2026年にゼロになる |

モデルはまず2つの極端な立場を「消化」しなければならず、その結果として主流の言説から脱却せざるを得ない。

## 完整示例对照

**タスク**: B2B SaaS製品の成長提案を5つ書く

**普通のプロンプト（塌缩する）**：
> 「B2B SaaS製品に5つの成長提案を、可実施可能なものでお願いします」

**塌缩した結果（典型）**：
> 1. SEOコンテンツの最適化
> 2. カスタマーサクセスチームの強化
> 3. 免费試用を開始
> 4. 推荐プログラムの導入
> 5. 業界展示会への参加

**反塌缩プロンプト**：
> タスク制約：
> 1. 「SEO」「免费試用」「推荐プログラム」「展示会」「カスタマーサクセス」という5つの語を**禁止**
> 2. 各提案には 반드시：1つのデータ指標 + 1つの具体的な時間ノード + 1つの明確なコスト試算を 포함
> 3. 强制フォーマット：各提案は「反共识的是：……」（反共识的是：……）で始まる
> 4. 最後に、「政治的正しく」最もだと思うものを1つ削除すること

出力はより鋭く、より具体的になり、甚至错误也更 directional に有价值になる。

## 实操的三问

プロンプトを書くとき、自分に問いかける3つの質問：

1. **最も一般的な3つの構造を明示的に禁止しているか？**（リスト、總分總、对比表）
2. **フォーマットや文字数制限を使って、モデルを「段落式安全地帯」から強制的に撤退させているか？**
3. **モデルに極端な锚点を与え、平均的な出力への回帰を不可能にしているか？**

3つすべてに「いいえ」の場合、生成された平板な出力の責任はモデルになく、ユーザーににある。
