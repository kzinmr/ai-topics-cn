# MCP（Model Context Protocol）— AIツール連携の標準規格

> トレンドランキング：#8（Juejin・V2EXにて計6件の言及）。言及数の割に、AIエージェント基盤を支える**イネーブリング概念**として極めて重要度が高い。

## 概要

MCP（Model Context Protocol）は、AIモデルと外部ツール・サービスを接続するための**標準プロトコル**である。中国語圏の開発者コミュニティでは、MCPを「**USBインターフェース規格**」に喩える表現が広く浸透している。USBがあらゆる周辺機器をPCに統一的に接続できるように、MCPはAIモデルがデータベース、ファイルシステム、Web API、開発ツールなどの外部環境と統一的にやり取りできる仕組みを提供する。

具体的には、MCP Serverと呼ばれるサーバーコンポーネントを介して、AIモデル（MCP Client）が外部能力を呼び出す。これにより、AIは単なるテキスト生成を超え、**実世界の環境と対話するエージェント**として機能できるようになる。

> "MCP——给你的AI员工打通外部能力"（MCPは、あなたのAI従業員に外部能力を開通させるものだ）
> — [AI 编程工程化：MCP](https://juejin.cn/post/7628542203947368490)（掘金）

## 技術的位置づけ

AIエンジニアリングにおける概念の階層を整理すると、MCPは最も構造化された外部連携レイヤーに位置する。掘金の分類記事では以下の階層が示されている：

```
Prompt（指示文）
  ↓ 自然言語による指示
Function Call（関数呼び出し）
  ↓ モデルが構造化された関数を呼び出す
Skill（技能包）
  ↓ ローカルな知識・ルールの集合体
MCP（Model Context Protocol）
  ↓ 外部ツール・サービスとの標準接続プロトコル
```

- **Prompt** は自然言語の指示にすぎず、外部連携能力を持たない。
- **Function Call** はモデルが特定の関数を呼び出す仕組みだが、実装がモデルやプラットフォームに依存する。
- **Skill** はローカルに定義されたルール・知識・ワークフローの束であり、モデルの振る舞いをカスタマイズする。
- **MCP** はこれらの上位に位置し、外部ツールとの接続を**プロトコルレベルで標準化**する。

> 参照：[Prompt、Agent、Function Call、Skill、MCP，傻傻分不清楚？](https://juejin.cn/post/7614205951297732654)（掘金、109いいね）

## Skills vs MCP

[[claude-code]] には二つの中核的な拡張メカニズムが存在する：**Skills（技能包）**と**MCP（Model Context Protocol）**。政采云技術チームの解説記事によれば、両者の違いは以下の通りである：

| 比較項目 | Skills（技能包） | MCP |
|---------|-----------------|-----|
| **本質** | ローカルな知識・ルール | 外部ツール接続プロトコル |
| **範囲** | プロジェクト内の規約・パターン | 外部サービス・API全般 |
| **実行場所** | ローカル（モデルのコンテキスト内） | MCP Server経由（外部プロセス） |
| **役割の喩え** | 「マニュアル・社内規定」 | 「USB接続ポート」 |
| **例** | コーディング規約、テスト方針、レビュー基準 | GitHub連携、DB操作、ブラウザ自動化 |

Skillsは「AIにどう振る舞うかを教える知識」であり、MCPは「AIが何にアクセスできるかを拡張する接続口」である。両者は補完的な関係にあり、実務では併用される。

> 参照：[什么是Skill以及和MCP的区别](https://juejin.cn/post/7628083295742165032)（掘金、政采云技術チーム）

中国の開発者コミュニティでは、MCPの実践的な活用が急速に広まっている。特に掘金（Juejin）では、MCPに関する実践記事が多数のエンゲージメントを獲得している。

## MCP Serverの実例

上記の実践記事および関連議論から、中国語圏で広く利用されているMCP Serverの典型例は以下の通り：

- **ファイルシステム操作** — ローカルファイルの読み書き・検索をAIに委譲
- **GitHub連携** — リポジトリ操作、Issue管理、PR作成の自動化
- **データベース接続** — SQL実行、スキーマ参照、データ分析
- **ブラウザ自動化** — Webページの閲覧・操作・スクレイピング
- **検索エンジン連携** — Web検索結果の取得と要約
- **ドキュメント管理** — Notion、Confluenceなどとの連携
- **コンテナ/インフラ操作** — Docker、Kubernetesの管理
- **監視・ログ連携** — アプリケーションログの取得と分析

これらのMCP Serverは、[[claude-code]] のようなAIコーディングエージェントと組み合わせることで、開発ワークフローの大幅な自動化を可能にする。入門者向けには保姆級（手取り足取り）チュートリアルも公開されている。

> 参照：[保姆級教程: Skills](https://juejin.cn/post/7628083295742165032)（掘金）

## Harness フレームワークにおけるProtocol層

[[harness-engineering]] の枠組み（arXiv 2604.08224 "Agent Harness" サーベイ）では、[[ai-agent]] の構成要素が以下の4層に整理されている：

```
Internalization（内在化）  — モデル内部の能力（推論、記憶）
Externalization（外在化）  — 外部ツール・環境との接続
  └─ Protocol層           — ★ MCPはここに位置する
  └─ Tool層               — 個別のツール実装
Interface（インターフェース）— ユーザーとの対話方式
Orchestration（統合制御）  — 全体のワークフロー管理
```

MCPは **Externalization（外在化）の Protocol層** に位置づけられ、エージェントがツールとやり取りする際の**通信規格を標準化**する役割を担う。個別のツール実装（Tool層）がMCP準拠で構築されることで、エージェントは新しいツールをプラグアンドプレイで追加できるようになる。

このHarnessフレームワークは V2EX でも紹介・議論されており、MCPをエージェント工学の文脈で体系的に理解するための参照点となっている。

> 参照：[V2EX — Agent Harness サーベイ紹介スレッド](https://www.v2ex.com/t/1206029)

## 批判と実用性のジレンマ（2026-04-18）

### 「嫌われているのに、なぜか手放せない」

2026年4月18日、V2EXで「**大家都在嫌弃 MCP 的时候我竟然发现有点离不开它**」（みんながMCPを嫌っているのに、なぜか手放せなくなっている）という投稿が話題となった。この投稿は、MCPがコミュニティで批判されつつも、実際には**代替不可能な価値**を持っているという逆説を浮き彫りにしている。

投稿者はHarnessプロジェクト「Chorus」（[[claude-code]]向けの自律的な要求→設計→承認→デリバリー パイプライン）の開発中に以下の洞察を得た：

1. **Skill/Promptでは不十分なシーン**: エージェントが長時間（30分以上）自律稼働すると、初期のPE（Prompt Engineering）を忘れてしまう。Skillに書いた指示は一貫して遵守されない
2. **MCPの真価**: 呼び出し返答中にPromptを注入する方式ではエージェントの**意図感知**ができない。MCPを使うことで、Agentが何をしようとしているかを外部から把握できる
3. **Reviewer Agentの安定起動**: 承認フローで独立したReviewer Agentを確実に起動するには、MCPのようなプロトコルレベルの仕組みが不可欠

> "MCP 这个协议刚出来的时候我感觉它到处透露着过度设计的味道... 但我在开发自己的 Harness 项目 Chorus 的时候又发现一些场景下没办法替换掉 MCP，主要的原因是通过 MCP 可以更好地感知 Agent 的意图"
> （MCPは出てきた当初、過剰設計に感じた... しかしHarnessプロジェクトChorusの開発中に、MCPを代替できない場面があることに気づいた。主な理由は、MCPを通じてAgentの意図をより良く感知できるから）
> — V2EXユーザー fennu2333

> **出典**: [V2EX — 大家都在嫌弃 MCP 的时候我竟然发现有点离不开它](https://www.v2ex.com/t/1206802) [T1]

一方で、MCPは具体的な実装例も増えている。V2EXで公開された「**Open Computer Use**」は、OpenAI CodexのComputer Use機能をオープンソース化したもので、MCPプロトコルにパッケージされており、全てのAIエージェントが即座に呼び出せるように設計されている。

> **出典**: [V2EX — 开源 Open Computer Use](https://www.v2ex.com/t/1206760) [T1]

### 貝殻 AI カスタマーサービス — 実務MCP活用例

中国の開発チームが$5,000を投資して開発した「貝殻 AI 客服」（シェルAIカスタマーサービス）システムは、MCPを外部システムとの接続手段として活用した実務事例。

- **従来のRAG客服**: チャット＋知識ベースの回答のみ
- **貝殻のアプローチ**: MCPを通じて外部システムと連携し、AIが実際に業務を遂行する
- SkillsとMCPを組み合わせ、異なるシーンの問題を解決

> "项目的核心思路不是'把大模型接进客服页面'，而是让 AI 真正进入客服系统的主流程"
> （プロジェクトの核心的思路は「大模型を客服ページに接続する」ことではなく、「AIを客服システムのメインフローに真正面から組み込む」こと）
> — 貝殻 AI 客服開発チーム

> **出典**: [V2EX — 花了$5000 刀使用 AI 开发了一套 AI 客服系统](https://www.v2ex.com/t/1206840) [T1]
