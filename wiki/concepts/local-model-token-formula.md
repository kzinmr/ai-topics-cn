# 本地模型部署 — Token输出性能计算公式

## 概要

本地部署大模型时，可以通过简单的物理公式估算token输出速度。核心参数是**显存带宽（Memory Bandwidth）**，而非仅仅是显存大小。

## 万能公式

```
Token输出时间 = 模型参数(BF16) × 2 bytes ÷ 内存带宽(GB/s)
```

### 实例：DGX Spark部署31B BF16 Gemma

```
273 GB/s (带宽) ÷ (31B × 2) = 理论最大 4.4 token/s
实际表现：约 2.5-3 token/s（算不错）
```

## 关键参数优先级

### 1. 显存容量（必要条件）
模型必须能完整加载到显存。显存只是**基本条件**。

### 2. 内存带宽（决定性因素）
带宽太低会成为「跛子」。几乎没人部署时注意这个配置。

> 「必须要看内存带宽（Memory Bandwidth），这个太低的话估计就是个跛子」

### 3. 推理速度基准
| 速度 | 体验 |
|------|------|
| <10 token/s | 明显延迟 |
| 15-20 token/s | 将就能用 |
| 25+ token/s | 看起来正常 |
| 50+ token/s | 流畅 |

## Mac特殊优化

macOS只要模型能加载到GPU，剩余内存就能用，速度不会很慢（20 token/s将就能用），冷启动稍慢。

## 本地模型实际用途（2026年现状）

### ✅ 适合
- OCR
- 知识库总结
- 配合线上模型做复杂代码生成，本地执行推理

### ❌ 不适合
- 超过线上模型效果
- 写代码（本地模型质量差距大）
- 实时性要求高的场景

> 「本地模型能做的事，ocr、总结做知识库、openclaw什么的推理也可以做——需要提前用线上模型完成复杂代码，本地执行推理一定要记得做好机子散热，一定！！一定一定！！」

## 硬件注意事项

- 做好散热（尤其Mac mini等紧凑设备）
- 英伟达卡 vs Apple Silicon有不同的最优配置
- 「双ISP家宽」IP不一定真能用，需多重验证
