# AI Agentチーム・スワームパターン

> **概要**: 単一Agentの限界（コンテキスト膨張、タスク競合、リソースボトルネック）を、複数Agentの協調で解決する開発パターン。

## 背景と動機

2026年4月、Juejin開発者「yezannnnnn」が**Claude Codeを使用して4つのAIエージェントチーム**を構築し、協調開発が実際に機能することを証明した。

> 「我用Claude Code搭了个四个AI的团队，居然真的能协作开发（附项目地址）」
> （Claude Codeで4AIのチームを組んだら、本当に協調開発できた。プロジェクトURL付き）

## 単一Agentの致命的問題

### コンテキスト膨張

- 単一Agentは長期タスク中にコンテキストウィンドウが溢れる
- 過去の指示・中間成果物・エラー情報が混在し、推論品質が低下
- 最終的に「何をしていたか」を見失う

### タスク競合

- 複数のサブタスクを並行して処理できない
- 直列実行による効率低下
- 依存関係の管理が困難

## 4AIチーム協調パターン

### アーキテクチャ

```
┌─────────────────────────────────────┐
│         Claude Code (ホスト)        │
│                                     │
│  ┌─────────┐  ┌─────────┐          │
│  │ Agent 1 │  │ Agent 2 │ ...      │
│  │(PM/設計) │  │(実装A)  │          │
│  └─────────┘  └─────────┘          │
│  ┌─────────┐  ┌─────────┐          │
│  │ Agent 3 │  │ Agent 4 │          │
│  │(実装B)  │  │(テスト)  │          │
│  └─────────┘  └─────────┘          │
└─────────────────────────────────────┘
```

### 役割分担例

| エージェント | 役割 | 担当範囲 |
|---|---|---|
| **PM/設計Agent** | タスク分解、計画立案、成果物レビュー | 全体設計、要件定義 |
| **実装Agent A** | フロントエンド開発 | UI/UX、コンポーネント実装 |
| **実装Agent B** | バックエンド開発 | API、データベース、ビジネスロジック |
| **テストAgent** | テスト作成、バグ検出、品質保証 | ユニットテスト、統合テスト |

### 協調メカニズム

1. **タスクキュー**: PM Agentがタスクを分解し、各Agentに分配
2. **成果物共有**: 各Agentの出力を共通リポジトリで管理
3. **フィードバックループ**: テスト結果を実装Agentにフィードバック
4. **コンテキスト分離**: 各Agentが独立したコンテキストで作業

## 実装上の課題

### 1. コンテキスト管理

- 各Agent間のコンテキスト共有方法
- 最新状態の同期メカニズム
- 競合解決戦略

### 2. エージェント間通信

- タスク完了通知の方法
- エラー伝播の制御
- 依存関係の表現

### 3. リソース最適化

- 各Agentのトークン使用量の管理
- 並列実行数の制限
- コスト効率の確保

## 今後の展開

マルチエージェント協調開発は、以下の方向に発展すると予想される：

1. **自動タスク分解**: AIが要件から自動的にタスクを分割
2. **動的エージェント構成**: タスクに応じて最適なAgent編成を自動選択
3. **分散実行**: 複数の物理マシンでAgentを並列実行
4. **自己最適化**: 実行結果から協調パターンを自動改善



### 実装パターン：ファイルシステム通信（2026-04-19更新）

Juejin開発者「yezannnnnn」の実装では、**ファイルシステムをAI間通信媒体**として使用する独自アプローチが採用された：

```
agentGroup/
├── max/          # 麦克斯 - プロジェクトマネージャー
│   ├── CLAUDE.md     # 役割定義と強制チェックポイント
│   ├── PERSONA.md    # AI人設
│   └── skills/       # PMスキルパック
├── ella/         # エラ - UI/UXデザイナー
├── jarvis/       # ジャービス - フルスタック開発者
├── kyle/         # カイル - テストエンジニア
└── shared/       # 共有オフィス
    ├── status.json       # チーム状態看板
    ├── notifications.json # AI間メッセージ
    ├── tasks/            # TODOリスト
    └── docs/             # 設計ドキュメント
```

**強制チェックポイントメカニズム**：
- 各AIのCLAUDE.mdに「鉄律強制流程」を定義
- タスク範囲確認→戦略読取→通知確認→タスク分解→Skill検査→実行選択→Git安全の7ステップ
- 物理実行必須：「頭で理解する」ではなく「実際にReadツールでファイルを読む」
- 自己監視プロトコル：プロセス違反検出時に自動修正

**Token節約効果**：
- 従来：200+ tokens（AIが自由に情報収集）
- 最適化後：50 tokens（Skill優先メカニズム）
- 節約率：**75%**
