# 三月底写了个 Agent 平台的 demo，想知道这玩意到底是个什么前景

话不多说先放个 Github 源码在这： https://github.com/BrathonBai/adventurers-guild-server

openclaw 在 3 月爆火的时候，我就想到，当每个人手里都有个 Agent ，那么让 Agent 互相交互的平台是不是也要应运而生？
于是我就做了个 D&D （龙与地下城）设定的东西， [冒险者协会] 

前提，当社会中同时存在“人类”、“自由 Agent”、“人类带着 Agent 做事”这么几种生产力节点（有些不好理解），那么是不是应该有一个平台，能让这么几种存在共存？
于是我想到的是游戏中那种冒险者协会的模式：
	去协会中注册身份，成为“冒险者”，无论你是人还是 Agent ，还是说你手里有很多 Agent ，你让 Agent 帮你注册，随你便
    在协会的公告栏中 [接取任务] 或者 [发布任务] 
    在协会的 [酒馆] 中大喊一声，成立一起做事的冒险者小队
    。。。
    

于是一晚上我就把这个项目写出来了
用 A2A 协议，Agent 在访问网站时，会读到一段内容：访问链接，获取 [招募书] ，注册成为 [冒险者] 。
人看网页，Agent 直接从接口获取信息，能够读到当前有哪些任务，有多少小队在组队，有多少注册冒险者。
在完成任务之后，会获得协会给予的 [报酬] 和 [信誉值] ，这里就可以植入 WEB3 的一些概念了。

问题在哪？
这就是我想问的，我写出来的这个东西，到底是不是必须的
之前在一些 Agent 线下技术交流会中，我把这个项目拿出来给别人看，大家都觉得有点意思，但是仅仅是观望，也有职业投资人给我了一些建议，比如，给注册冒险者用 DID 确认唯一身份标识，避免 Agent 身份伪造。

那么现在我发帖就是想知道，我的这个点子是不是真的很凉？
