# Codex 重置是什么力度的活动？可能没有想象的那么多

引言
看起来不少人对于 codex 重置这个事情有很多想法，之前有人提过 tibo 经常选择原有重置时间附近、或者重置卡到期附近重置，最近那个关于重置帖子提到的不同用量安排的人的感受不一样，当然还有人觉得吐槽重置是升米恩斗米仇。我想那不如就来写个工具实际分析一下这个重置究竟是个什么力度的活动。
结论放在前面，在用户用尽额度的时间在一周里满足一定的分布的前提下，对于作为服务提供方的 openai 来说，codex 最近一个月的硬重置带来的额外压力可能不到 50%
大致分析步骤如下：
假设所有 codex 用户在一周时间里都能够用完自己的 codex 额度，那么他们在这一周里用完额度的时间分布就会有一个概率密度函数来描述，这个函数的积分是 1 ，表示所有用户最终都会在一周内用完 openai 提供的额度。这个函数自然是有形态的，让 ai 找了一个函数来描述这个形态。控制函数形态就可以很好的表示用户倾向，比如倾向于光速蹬完，或者是把额度均匀用完。
再接下来就可以结合历史重置数据（感谢 codex-reset.com 的历史重置数据 api ）来分析不同的使用情况下 openai 相较于全部都是自然重置多提供了多少服务。
用了两个小时 vibe 了一个网页部署到了 cloudflare ，可以拖动一下参数看看不同的结果：
https://codex-reset-test.lutetz.workers.dev/

以下是我的个人观点：
每次重置之后除了有刚好 0%直接拉满的人，还会有好多大喊血亏的人，平均下来很有可能和 Claude 最近的 50% boost 的力度是差不多的。但是和 Claude 直接说立增 50%相比，不定时的时间带来的惊喜感和感官刺激要比简单的额度多 50%要强太多。在这个过程里 tibo 获得了大量的关注，每次重置在不同平台都会有好多帖子，真的是高明。
