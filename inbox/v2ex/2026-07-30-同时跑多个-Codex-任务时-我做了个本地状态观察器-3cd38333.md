# 同时跑多个 Codex 任务时，我做了个本地状态观察器

最近用 Codex 并行处理多个任务时，一个实际痛点是状态分散在不同会话里：任务是不是还在执行？最终结果有没有看过？是不是卡在需要我批准、回答或浏览器交互？
我做了一个开源 macOS 菜单栏应用 AgentMicro，只读观察本机 Codex Desktop / CLI 任务，把这些状态放到一屏里。
实现时最在意“别把猜测显示成事实”：

只有明确的 turn 开始、活跃推理、工具调用/执行等本地证据才显示思考中
final answer 会立刻结束蓝色状态，不等进程退出
明确的提问、批准请求或浏览器 handoff 才会进入橙色，并持续到用户继续任务
阻塞失败才显示红色；已恢复的警告和用户中断不会被误判
Desktop 完成结果会同步本地未读状态；从 AgentMicro 打开准确会话后立即已读，后续新完成结果仍可重新变绿
证据不足就降级为空闲，不靠“文件刚改过”猜运行中

UI 保持很小：当前工作任务优先、项目和标题、当前 turn 时长、fast mode 闪电标记；点击 Desktop 行通过 deep link 回到对应会话。菜单栏六格图标映射前六个任务，工作中时才有轻微动画。
它不上传 Prompt 、回复、代码、命令输出或会话文件；不读 Keychain ，也不代替用户批准/操作任务。基础模式不需要辅助功能权限；可选增强检测也只是本地只读。
macOS 14+，Apple Silicon / Intel 。
