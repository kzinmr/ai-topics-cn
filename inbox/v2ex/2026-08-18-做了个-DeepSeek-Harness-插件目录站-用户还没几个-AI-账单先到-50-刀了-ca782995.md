# 做了个 DeepSeek Harness 插件目录站，用户还没几个， AI 账单先到 50 刀了

最近 DeepSeek 发布了 DeepSeek Harness ，感觉还挺好玩的，就像先给了你一个骨架，可以在上面随意搭建，然后做出自己的 AI Agent 。我就赶紧开始折腾了。
开始折腾后的第一件事就是找插件，然后很快我就迷失在一堆 DSH 插件里了。这个生态发展得是真的快，GitHub 上不断有新插件冒出来。我一开始也是直接在 dsh-plugin topic 里面找，后来插件一多，麻烦也跟着来了：不知道每个插件是干什么的，不知道自己该用哪个；有些插件看着还不错，安装以后却不能用……
我就想着，要不做个插件导航吧。
但我也不想只是简单收集一堆链接，最好能把大家最关注的信息都整理出来，这样点开一个插件就能一目了然。GitHub 上每个作者写 README 的习惯和风格都不一样，如果每个仓库都要自己一点点研究，还是挺累的。所以我就想，不管原来的 README 写得怎么样，到了网站上，都尽量按照同一套结构，把需要看的信息直接展示出来。
为了这个，我和 AI 配合，前前后后大概做了下面 8 件事：


先是让网站能自己找插件。现在它会定时去 GitHub 搜索 dsh-plugin 相关的仓库，不用我每天手动翻 topic 看有没有新的。


找到以后，还要读取 README 、package.json、release 、commit 、Star 等信息，先用提前设计好的规则做一轮分析和筛选。后面仓库有变化，网站也会继续同步；如果同步失败，就按指数退避重试，过一会儿再试。


最麻烦、也最烧钱的，就是让 AI 解读插件了。这块前前后后换了好几版提示词，要把写法各不相同的 README ，还有藏在其他文件里的关键信息，拆成统一的结构，再判断它是不是 DSH 插件、能做什么、适合谁用、有什么限制。验证的时候，我还让多个 AI 同时出结果，再对比选出更合适的那一版。
