# Cursor 3.9 版本，大陆地区无法使用高级模型的解决方案探讨

笔者前两日，cursor 自动更新后到 3.9 之后，高级模型直接消失，走起来就是个 Composer2.5 Fast 。这个模型不是不能用，而是高级模型用起来更得劲。之前配置的连接方式 1.1 啥的都没改，梯子也没变化，就很奇怪。
上网搜索了下，似乎这个版本让之前的一些规避措施失效了。笔者通过降低到 3.8 版本，短暂解决了这个问题。官网自己就提供旧版本的下载： https://cursor.com/cn/download
在 3.9 变更回 3.8 之前，我让 Composer2.5 自己诊断了下原因，并在更新为 3.8 之后，又让模型诊断对比了下。可能的原因如下：
3.9 的模型可用性解析挂掉了
关键日志：
Model reset by fixUnavailable
previousModel: claude-opus-4-6
newModel: default
availableModels: default, composer-2.5, grok-build-0.1, grok-4.3, kimi-k2.7-code, glm-5.2
directlyAvailableCount: 0
resolvedAvailableCount: 0

也就是说，回退解决的是模型可见性。模型这部分，3.9 引入了一个新东西，用模型参数 + slug 版本解析替代 3.8 的简单 modelName 匹配。那我限制这部分功能，或者给他也加上代理可行吗？
