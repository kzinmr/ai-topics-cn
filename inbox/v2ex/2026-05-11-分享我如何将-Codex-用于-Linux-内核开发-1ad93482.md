# 分享我如何将 Codex 用于 Linux 内核开发

有四个 agent 角色：调度（主）、计划、执行、审核
所有的 agent 都使用 gpt-5.5-xhigh
因为内核总是容易崩溃，所以

用 watchdog 保证内核崩溃后会自己重启
用 pstore/ramoops 保证信息不会丢失
驱动编译成模块的形式，避免一开机就崩溃

Codex 跑的时候我大部分时间都在摸鱼，但是也会常开一个新的 Codex 用于了解现在的代码实现方式，看看和我预想中的是不是一样的，不一样的话就和 AI 讨论一下用什么样的方式更加好，然后更新信息给调度 agent 。新项目还是得一直盯着，避免技术路线错了，过了这个阶段基本的流程都打通了，提需求就可以了。
可以这样做也应该和我所在的公司规模小有关系，最重要的是把功能实现，基本没有规范性方面的要求。
用的是 ChatGPT Pro $200
