# vibe 用多 agent 的好处是什么？

最近老看见 rmux 的身影，没用过。
我自己用的 termius ，一个 workspace 开多个终端进行 boardcast input 最多了。
我也不是单一 agent 信徒，有不错的 agent ，引入自己的 flow 也是不避讳的。
但我想不通，很多人用 4-5 个 agentic ide 是做什么的？
比如 claude code 做编排以及 planner 我能理解。基本用的也是 claude 自家模型。
那么为什么写后端用 vibe ，前端又用 grok ，然后 apis 用 antigravity ，最后 review 再用一个 codex 。
这。。。。
ai 没有这种人类所谓的分工吧。我觉得第一梯队的模型，差距不会天差地别吧。大步了让 claude 控制 routing 对细分的 task 进行路由就行了，让 claude 根据模型 benchmark 偏好进行切换。
而且一旦这么分离了，上下文呢？我看 rmux 是截图输出进行管理。有必要嘛？
一个项目一个 agent 负责，你不让 agent 停，你就同时开多个项目跑就行了。可以做成旋转木马的。
这安排多个 agent 并行，还是同类 ide ，就有点不理解了。真当牛马用啊。压榨的没人性了。
你加 loop 或者加 graph nodes ，都没意见，明确需求后，不就是一顿挂机嘛。理解不能。
自己还是单 agent 模式。所以对多 agent 的工作流有点兴趣，但也怕过度工程化。求解。
