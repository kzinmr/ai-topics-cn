# 不吐不快， cursor 在变相折磨老用户

我一直是 20 刀/500 次的老用户。只用 opus4.6
平时用量还是很大的，每个月都超，超了就是$0.08 一次

在调用 opus 4.6 的时候，不论是 2 万 token 还是 1000 万 token ，每次对话都是计数 2 次
最近几个月，一直有这样一个情况（必触发）,似乎是一种针对我们这种老用户的策略
具体的
在某次对话，token 量过大的时候（目前看，只要大于 500 万就会触发）
比如，某次对话消耗500 万token ，cursor 计数两次。
那么之后将不允许对话，指的是无法继续在原有对话框进行对话。
表现不论发送什么消息都会提示 take longer than expected ，取消重新发送也依旧。
解决方案
唯一的解决方案，就是新开一个对话，免费送 cursor 一些额度（就是随便聊点，比如问他在吗这种简单的对话），才能有概率恢复

比如上图，我消耗了一次 500 万的 token 之后。
之后所有的 - 都是我在那个对话框中继续聊天，怎么都不会回复我，永远都是超时
但是，新开一个对话框，问简单问题，是可以秒回的
只有这样，似乎是用多次几万的 token （那些 2 万的对话），意思让 cursor 也嫖我几次
才能激活 500 万的 token 的聊天，继续对话。
猜测
这不是一次，是每次，每次只要单次用量一大，一定触发这个问题。
体验下来，不是不回复，是在单次消耗了巨大 token 之后，直接拦截了后面的对话。
只有满足某个规则之后，才能继续对话
感觉似乎是，在拿我做 T ？
做低次均对话 token ？
