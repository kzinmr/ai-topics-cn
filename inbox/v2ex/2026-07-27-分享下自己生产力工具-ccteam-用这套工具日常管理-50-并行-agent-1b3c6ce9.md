# 分享下自己生产力工具 ccteam，用这套工具日常管理 50+并行 agent

以前用 Claude Code 、Codex 、Grok ，其实都是单打独斗：开一堆终端，这边聊半截、那边写一半，进度散得到处都是。agent 干完一步就停在那等我回车；我去接杯水，活就卡死了。人得一直钉在电脑前，比写代码本身还累。
烦够了，我干脆把想要的工作方式做成了开源项目 ccteam——不是再造一个新 agent ，而是把已经在用的这些 code agent 编成一支真正能协作的团队。
现在比较常见的一天是这样的：出门前丢给 Codex 一个长活；吃饭时在 Telegram （飞书也行）瞄一眼进度、补一句要求；回来测试已经跑完了。中途想插话，浏览器控制台说一句就行。多个会话可以互相派活、接力往下干——我不用一直守着，它们也不用一步一等我。
组队之后，各家也真的各干各的强项（这是我自己用下来的感受）：

Grok 快，探路、要个第二意见最顺手
Claude 想得深，但额度金贵，留给关键规划和难判断
Codex 扛长程编码稳，闷头实现、跑测试，我比较放心

不是谁取代谁，是打配合。跨厂商的任务能派出去、收回来，会话和花费也在一个地方看着——对我这种一天要跟好几个 agent 打交道的人来说，这才像「团队」，不是一堆孤立聊天窗。
开源（ MIT ），装上就能用，也可以 fork 成更适合自己的方式：
https://github.com/firstintent/ccteam
如果你也同时用好几家 code agent ，却发现自己成了它们之间最忙的接线员——不妨试试。觉得有用给个 star ，你可以 fork 定制适合自己的生产力利器。
