# 花了 200 亿 Token 用 CodeX 把一个英文计算器站推上线后，我发现公式反而最省心

最近总算把一个拖了挺久的项目放到线上了： https://calculatorqueen.com
我之前想做一个工具平台，帮助用户解决各种问题，同时也让用户通过每个页面学到这个计算器所算的东西。前后下来开了 3 个 Codex 20X 的账号，正好碰上最近重置多，每天都用尽全力蹬，总共用了 200 亿左右的 Token 。
最后做出来的平台叫 CalculatorQueen ，是个英文在线计算器站。金融、健康、数学、日期、建筑、单位换算这些常见分类都有。
我不希望它只是扔给用户一个答案，所以大部分页面都会尽量把单位、公式、计算步骤、假设和限制一起写清楚。至少算出一个奇怪结果时，用户还能顺着步骤看看是哪里出了问题。
有几个页面比较能说明我想做的方向。比如 Grams to Cups Converter，它不是拿一个固定比例硬换算，而是按 110 多种食材分别计算；Chinese Zodiac Calculator 也不是简单按 1 月 1 日切换生肖，而是用了香港天文台的农历新年边界数据。还有一个偏程序员趣味的 Calculator Infinity Trick，可以实际看看 overflow 、undefined 、error 和 infinity 有什么区别；做视频或动画的也可以试试 FPS Calculator，它能把总帧数、真实时长和 non-drop timecode 对起来。
最开始我以为最难的是公式。
真正准备上线才发现，公式反而挺“听话”：输入是什么，输出就是什么，错了还能写测试抓出来。更磨人的其实是另外一些事情：

预览环境会不会不小心被搜索引擎抓走；
正式环境会不会继续带着 noindex ；
旧地址到底由 Worker 还是静态资源负责跳转；
查询参数和尾斜杠会不会让同一个页面出现好几个版本；
页面虽然能打开，但内容是否真的准备好进入搜索结果。
