# 一个人搞了个浏览器插件,量很小但很稳,聊聊为什么我不打算做大

分享一个不算成功但也没死的项目。是个 Chrome 插件,功能很单一:帮人自动整理浏览器里开着的几十个标签页,按域名和最近使用时间分组,一键收起。做了快两年,现在日活大概 1200 左右,付费用户 300 出头,一次性买断 29 元,没有订阅,月收入基本在 2000-3000 波动,谈不上暴富但覆盖了我自己的服务器和 API 成本还有富余。
这个东西完全是自己用出来的。之前开了太多标签页,电脑经常卡死,写了个脚本自己用了半年,后来想着顺手发到 Chrome 商店,没做任何推广,靠商店自然搜索流量涨起来的。上线第一年基本没管它,直到有次看后台发现日活涨到了大几百,才认真做了付费墙。
说实话这个项目的数据放在 V2EX 不算亮眼,但我想聊的是另一件事:我刻意没有把它做大。有段时间用户反馈很多想要的功能,比如同步、团队协作、AI 自动分类,如果都做进去,理论上确实能冲一波付费转化。但算了笔账,这些功能要么涉及后端存储成本陡增,要么要维护多端同步,一个人根本忙不过来,一旦做大了反而可能因为服务不稳定被骂,得不偿失。
所以现在的策略就是保持功能极简,一次性付费,没有服务器依赖用户数据本地存储,几乎零维护成本。这两年里我真正花在这个项目上的时间加起来可能不到一个月,剩下时间都在做本职工作或者别的尝试。
写这个帖子是想问问大家:独立开发是不是一定要追求"做大"才算成功?像我这种刻意控制规模、换取低维护成本和自由时间的做法,有没有其他人也在这么干?挺想听听不同的思路。
