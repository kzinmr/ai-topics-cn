# 🔥 扒了一遍 Cursor 的底层协议，自己也卷了个平台

扒了一遍 Cursor 的底层协议，顺手做了个平台
为什么中转里永远只有 GPT / Claude ，没有 Composer ？
抓了几天包，原因就两层。
一、Composer 没得卖
从 Cursor 2.0 起，Composer 是自研模型，不是功能名。Tab 同理。
这两个模型不对外开放 API 。你填的 base_url 只能走第三方模型目录，Cursor 自己的权重不在里面。
二、协议也接不上
Cursor 客户端到服务端不是 REST ，而是 Connect + HTTP/2 ，载荷是 protobuf 。关掉 HTTP/2 ，很多能力直接挂。
对话、模型列表、代码库索引、鉴权用量，各走各的通道。
其中两条比较关键：

@codebase：Merkle 树增量同步，只传差异，不全量扫仓库
Agent：双向流。模型生成一半，等客户端读/写文件，回传后再继续，一轮可能来回十几次

所以很多「支持 Cursor 」的中转，其实只接了 chat/completions 。能聊是必然，没有 Composer 也是必然。
